# 跨海通道开通后的渔港经营成效评估

业务资料均为合成记录。表头字段及跨表引用见 `fixtures/format.json`。
本项目仅依赖 Node.js 标准库，在 Node.js 22.23.4 上运行。

## 数据约定

周号按各地合作社同一季历。交易 type/buyer 对应本地货权：wholesale 是入手后再售，
visitor 为最终购买；同货批、同经营者、等额的 dock 和 online 编号可为同一成交的渠道再报；
未能唯一解释的记录列待核。迁转核实日期以 verified_week 为准，当前村归属以有效周为准。
operator-open 补充缺报和停业状态，省略并不代表失业。
对照港分流排除比率为经新桥访问数除以观测流量，门槛为 fund 中比例。扶持申请按同一失收期
和家庭计，同户的已发款先占名额。新候选优先登记有凭据的正损失，高损失优先，等损失时按
申请标识稳定排序，超出家庭或基金余额的部分候审。

CSV 使用 UTF-8、逗号分隔，无引号与内嵌换行。未提供的字段是空字符串，作为关系值的 `-`
表示不适用。多值字段用竖线分隔，数值和日期单位见业务约定。

## 分析口径（季度会原口径，见 `outputs/baseline/caliber.json`）

1. **货权去重**（`src/canonical.mjs`）
   - 同 lot、同经营户、等额且 buyer 一致的 dock/online 一对凭证合并为一笔成交，保留两个凭证号；
   - wholesale 与 visitor 货权不同，分别汇总。因果与扶持的主口径只用 visitor 最终购买，
     批发转售在 `causal.wholesale` 单列，不与游客收入相加；
   - 同键且无法唯一解释的重复记录进待核队列，不静默丢弃、不直接计收入。
2. **名册与归属**（`src/roster.mjs`）：迁摊按 effective_week 滚动归属，verified_week 单列；
   迁摊不新增经营户，同户多个经营点共用一个家庭额度。
3. **营业状态**（`src/causal.mjs` 面板）
   - not-open（实际停业）、no-report（缺报）、weather-closed（风浪停航）周分别剔除并计数，
     不以零值填充，无观测周不推断为零；
   - 停业/缺报登记与实际成交凭证冲突时，以交易凭证纳入并保留 `statusConflict` 标记；
     风浪停航属外部冲击，即便有凭证也不进常规可比样本。
4. **分流评估**（`src/spillover.mjs`）：对照港通车后任一周 `via_new_bridge/traffic ≥ 门槛`
   即认定有足够分流证据，移出干净对照组并单列，不能当作完全未受影响。
5. **因果证据**（`src/causal.mjs`）
   - 处理组=通车港经营户，干净对照组=无分流证据对照港经营户，污染港经营户不并入对照；
   - 报告通车前 OLS 趋势、组-周均值 DiD、通车前内部安慰剂窗口；
   - 不确定性用固定种子的周级区块自助法（默认 2000 次）给 90% 区间，并按区间是否跨 0、
     样本户数量给出证据等级与局限说明；
   - 均值与收入分布只在实际可比的经营户-周上计算，剔除口径随结果一起披露。
6. **户级损失**（`operatorCounterfactualLoss`）：反事实 post 均值 = 本户通车前均值 +
   干净对照组组级变化；通车前无可比观测的户标记为不可估，不用片区增减替代户级判断。
7. **扶持分配**（`src/support.mjs`）
   - paid 先占家庭额度与基金；新候选须有登记正损失，按金额降序、申请号升序；
   - 每户批准额受 per_household 余量与基金余量双重约束，放不下的部分进待审并写明原因；
   - 零损失/未核实列待核资格；台账反事实损失与登记损失不符的，资金动作与复核标记分离输出。
8. **匿名发布**（`src/publish.mjs`）：村、片区、决策桶内可识别主体 < publish_minimum 即抑制；
   村与片区同时为小样本时禁止用已发布格凑差反推单户；项目级资金总额不细分主体，始终与
   fundLedger 占用恒等，桶级抑制金额计入 suppressedApproved 并完成两层对账。

## 目录结构

```
src/            分析管线（纯函数模块，仅用 Node 标准库）
  csv.mjs       CSV/JSON 读取、数值解析、引用校验、输入哈希
  canonical.mjs 渠道再报合并、批发/游客分列、待核队列、周收入汇总
  roster.mjs    经营户/家庭名册、迁转归属、营业状态索引
  spillover.mjs 对照港分流比率、门槛判定、干净对照组
  stats.mjs     均值/分位数/分布/OLS 趋势、可复现自助随机数
  causal.mjs    可比面板、DiD、安慰剂、不确定性、户级反事实损失
  support.mjs   扶持排序、家庭额度与基金占用、待审/待核资格
  publish.mjs   小样本抑制、凑差防护、资金对账
  pipeline.mjs  主管线（目录入口与内存 bundle 入口同一口径）
  review.mjs    补数装载、内存合并、结论 diff、已拨付复核
tools/          命令行入口（analyze / review-cli / check-materials）
fixtures/       季度会基线交接资料
fixtures-review/ 评审补录（淡季交易、状态更正、凭据覆盖、人工说明）
test/           node:test 测试套件
outputs/        运行产物（已 gitignore，可随时重生成）
```

## 运行

```bash
npm ci --ignore-scripts --offline   # 准备工作区（本项目无第三方依赖）
npm run check:materials             # 校验交接资料表头与引用
npm test                            # 全部口径测试
npm run analyze                      # 基线季度会分析 → outputs/baseline/
npm run review                       # 补数复核 → outputs/review/
```

也可指定目录：`node tools/analyze.mjs <资料目录> <输出目录>`、
`node tools/review-cli.mjs <补录目录> <输出目录>`。

## 基线合成数据的主要结论（随产物可复算）

- 112 条凭证合并 1 对渠道再报后为 111 笔成交：游客口径 110 笔、批发 1 笔（TX1，单列）；
- P3 第 5 周分流 60/140 ≈ 0.43 跨过 0.20 门槛，移出干净对照组；P4、P5 为干净对照；
- 游客口径 DiD 为负但 90% 自助区间跨 0，安慰剂窗口量级不小，且处理组通车前仅 1 户有观测，
  证据等级为"有限"——客流显著上升与户级收入效应之间不能直接划等号；
- 扶持：C1 已拨付先占 F1 额度，C2 仅余 50 家庭额度（210 待审），C3 零损失列待核资格，
  C4 登记损失与台账反事实不符并带复核标记；基金占用 630、余 20、待审 210；
- 各片区/村与决策桶在门槛 3 下均为小样本，公开金额抑制，项目级总额仍与资金占用对账相等。

## 补数复核

`fixtures-review/` 不改动基线资料，叠加：淡季补录交易、营业状态更正、申请凭据整行覆盖、
人工说明。重跑后 `outputs/review/review-diff.json` 给出：

- 新增规范化成交与面板格变化（如 V3 第 3/4 周、V5 第 7 周由剔除转为可比）；
- DiD、区间、证据等级与户级损失的前后变化；
- 候选翻转（如 C4 由建议批准变为待核资格）与已拨付款项的另行复核清单；
- `audit-trail.json` 留存两次运行的输入文件哈希与口径，支持回查季度会原口径。
